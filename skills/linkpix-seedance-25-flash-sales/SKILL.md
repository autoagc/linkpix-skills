# Seedance 2.5 Flash 电商带货视频 | LinkPix

用商品图和卖点生成带货短视频、商品展示视频与信息流广告视频。Seedance 2.5 Flash 与 Seedance 2.5 同属营销广告档，按秒单价更低、最短 4 秒起，适合预算有限时批量试素材，也适合主图视频这类短版位。

## 交付标准

- **已生成**：交付 CLI 返回的真实视频，写明时长、画幅、所用参考素材，附逐条核对结论和 CLI 返回的实扣积分。
- **本轮出不了视频**（没有 CLI 或密钥、正在等用户确认报价、调用失败、任务还在排队）：交付「成片方案」，开头写明「视频尚未生成」。方案包含分镜表（时段、画面、声音）、完整提示词、可直接提交的 `params.json`，以及用户下一步只需做什么。已提交的任务要写明任务 ID 和续查命令。方案要写到拿去就能提交的程度，不能只回一句"任务未完成"。
- 无论哪种情况，都不声称已出片，不编造任务 ID、视频链接或扣费；不编造商品参数、认证、功效、价格和优惠。

## 工作流程

1. **读需求**：从用户的文字和图片里提取商品、投放平台与版位、时长、画幅、语言、核心卖点和必须保留的外观细节。非关键信息缺失时按下文常规做法补上并标为「假设」，放到回复末尾集中确认，不为此停下来追问。
2. **要参考图**：Seedance 2.5 Flash **必须有参考图**。用户没给商品图时先要图，不要只凭文字描述提交；同时可以先把分镜和提示词写好交给用户。
3. **定时长与画幅**：时长 4–30 秒任选整数，**提交时必须显式传 `duration`**。没说时长时按版位提议：主图视频 5–8 秒，信息流广告 10–15 秒，种草或测评 15–30 秒，并在确认参数时告诉用户可以改；时长越长越贵。画幅只有 `竖屏 9:16` 和 `横屏 16:9`：抖音、快手、视频号、TikTok、小红书用竖屏，Amazon、YouTube、商品详情页用横屏。用户要 1:1 或 3:4 时，说明本模型不支持，可以生成后裁切，或改用支持该画幅的模型。
4. **写分镜与提示词**：按秒排镜头，依次写「开场钩子 → 卖点展示 → 使用场景 → 收尾定格」。每个镜头写清画面主体、动作、运镜、光线与场景。视频自带声音，旁白、台词和音效都写进提示词，原文用「」给出，并写明语言。商品外观（颜色、按键、logo、包装文字）逐项要求与参考图一致。画面里不放精确价格和长段文字，这些留到后期叠字。
5. **提交**：环境就绪时按「调用青虎AI」报价，用户确认后提交，确认消息里附上整份方案。环境不就绪时直接按交付标准给出成片方案，不反复安装或索要密钥。
6. **核对**：成片后按「核对与交付」逐条检查再交付。

## 调用青虎AI

本技能使用 `Seedance2.5 Flash`。它与 `Seedance2.5` 是两个不同的模型，`modelLabel` 要逐字写全，不能省掉 Flash。目录里没有该模型或显示维护中时如实说明，换不换模型由用户决定。

1. **环境**：`qhkit --version` 需 ≥ 0.15.0。缺失或版本过旧时运行 `npm i -g @iqinghu/qhkit@latest`；网络慢时加 `--registry=https://registry.npmmirror.com`，没有全局安装权限时改用 `npx -y @iqinghu/qhkit@latest <命令>`。仍装不上就按交付标准给出方案。
2. **密钥与站点**：`qhkit config show` 返回的 `site` 须为 `cn`。没有密钥时，请用户在[青虎 API Keys](https://www.iqinghu.com/workbench/dashboard/api-keys)创建国内站密钥，拿到后运行 `qhkit config set --token <密钥> --env prod`；在此之前先交付成片方案。密钥不写进参数文件，也不在回复里复述。
3. **查选项**（只读，不需确认）：运行 `qhkit video options '{"queryParams":["modelLabel","models"]}'`，确认 `Seedance2.5 Flash` 在列，读它在 `models` 里的条目：`durationRange`、`creditsPerSecond`、`orientationLabel`、`maxReferenceImages`、`maxReferenceVideos`、`maxReferenceAudios`，以及 `referenceImageRules` / `referenceVideoRules` / `referenceAudioRules`。`maintenance: true` 不可提交，`notice` 含「即将下线」时先告诉用户。
4. **参数**：`modelLabel`、`duration`、`prompt`（最多 5000 字）必填。`uploadedImages` 必填，可填本地路径或 http(s) URL，CLI 会自动上传；2026-11-19 的规则是最多 10 张、短边 ≥ 300px、宽高比 0.4–2.5、单张 ≤ 10MB，超过 10MB 先压缩副本（长边 ≤ 2048px）。`imageUsage` 是一段对全部参考图生效的用途说明，不超过 200 字。参考视频用 `uploadedVideo`（可传数组，mp4/mov，单条 2–30 秒，总时长 ≤ 30 秒）；用户自带的音频用 `uploadedAudio`（可传数组，wav/mp3，单条 2–15 秒，总时长 ≤ 15 秒）。`orientationLabel` 取 `竖屏 9:16` 或 `横屏 16:9`；`languageLabel` 可选，取值来自 `qhkit video options '{"queryParams":["languageLabel"]}'`；`count` 1–8，同一份参数出多条变体时才加大。
5. **报价与确认（硬规则）**：参数写入 UTF-8 的 `params.json`，运行 `qhkit video estimate '@params.json'`，报返回的 `credits`。把模型、时长、画幅、语言、条数、参考图和参考视频/音频、提示词和预计积分一次性列给用户，**用户明确同意后**才运行 `qhkit video generate '@params.json'`。`enough:false` 时先说明余额不足；返回 `referenceImageRequired: true` 说明本次参数还没带参考图，要先向用户要图。任务提交后不可取消。
6. **轮询**：`generate` 只提交任务，立即返回 `videoTaskId` 和本次扣费 `credits`。提交后马上告诉用户任务 ID 和预计耗时，然后每 30–60 秒运行一次 `qhkit video status '{"videoTaskId":"<任务 ID>"}'`，直到 `stage:"done"`。视频任务最长可达 40 分钟，不要提前放弃，也不要重复提交；本轮等不到结果时，交付任务 ID 和续查命令。
7. **出错**：失败时 stdout 为 `{"ok":false,"stage":...,"message":...}`，把 message 原样转告用户（常见：积分不足、内容审核未通过、模型维护中、素材不符合规则）。`stage` 为 `version` 或提示"未知命令"时先升级 CLI，再重试一次；同一个错误不反复重试。

Windows：PowerShell 5.1 会吞掉命令行 JSON 里的双引号，参数一律写进 UTF-8（无 BOM）文件，命令里写成带引号的 `'@params.json'`（不加引号时 PowerShell 会把 `@` 当作展开运算符而报错）。再加 `--out result.json`，用 `Get-Content -Raw -Encoding UTF8 result.json` 读结果，避免中文乱码。看到乱码时不要据此判断模型不存在。

## 核对与交付

- 从 `status` 返回的 `videos` / `primaryVideo` 取视频并下载，核对时长、画幅、条数是否与提交参数一致。
- 对照参考图检查商品外观（颜色、形状、按键、logo、包装文字）是否走样；旁白和台词的语言、内容是否与提示词一致，有没有出现提示词之外的功效或数字。
- 在同一轮回复里交付视频和"生成完成"的说明，写明本次实扣积分。不合格的片子如实标出并说明原因，不要只报好的、隐去差的；需要重做时先说明原因和预计积分，经用户同意再提交。

- 复刻对标视频链接走「Seedance 2.5 Flash 爆款视频复刻 | LinkPix」（`linkpix-seedance-25-flash-clone`）。
